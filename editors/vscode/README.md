# mzs для VS Code

Подсветка синтаксиса, автодополнение, всплывающие подсказки и диагностика для языка mzs
(описание языка — `README.md` в корне репозитория, спецификация — `SPEC.md`).

Расширение написано на чистом CommonJS **без единой зависимости и без шага сборки** —
его достаточно положить в папку расширений, `npm install` не нужен.

## Установка

```sh
# 1. собрать интерпретатор, если его ещё нет
cd /home/alexander/go-test-project/mzs
go build -o ~/bin/mzs ./cmd/mzs

# 2. подключить расширение симлинком (правки видны сразу)
ln -s "$PWD/editors/vscode" ~/.vscode/extensions/mzs-1.1.0
```

Перезапустите VS Code. Если `mzs` не лежит в `PATH`, укажите путь в настройке `mzs.path`.

Для установки из VSIX (нужен `npx @vscode/vsce`, требует сети):

```sh
cd editors/vscode && npx @vscode/vsce package
code --install-extension mzs-1.1.0.vsix
```

## Что умеет

| Возможность | Как работает |
|---|---|
| **Подсветка** | TextMate-грамматика по SPEC §3: строки с интерполяцией `${}` и `$globals` внутри, «сырые» строки `'…'`, регулярки `/…/imxsu` с якорями, квантификаторами и классами, числа во всех системах счисления, ключи словарей `[a: 1]`, параметры замыканий `(x) ->`, `include`/`export`, имена модулей, комментарии `#` |
| **Автодополнение** | После `include ` — встроенные модули с пометкой, какой флаг им нужен; после `модуль.` — его члены (для своего `.mzs` — реально экспортированные из него имена); после `.` — методы получателя (тип выводится из литерала слева); иначе — встроенные функции, ключевые слова, подключённые модули, а также функции, локальные переменные и `$globals` из самого файла |
| **Подсказки при наведении** | Сигнатура, описание и пример из SPEC §12; для члена модуля — ещё и что нужно `include` (и какой флаг) |
| **Диагностика** | `mzs --check -` по мере ввода: буфер уходит в stdin, поэтому ошибки видны **до сохранения файла**. Предупреждения показываются как warning, ошибки — как error |
| **Команды** | `mzs: запустить файл`, `mzs: выполнить выделенное как однострочник` (<kbd>Ctrl+Shift+E</kbd>), `mzs: показать поток токенов`, `mzs: показать AST` |
| **Иконка файлов** | `.mzs` получает собственную иконку в проводнике — светлый и тёмный вариант логотипа (`icons/mzs-*.svg`), плюс тема иконок **mzs (Seti)**: Seti целиком и `.mzs` с логотипом |
| **Сниппеты** | `inc`, `incfrom`, `expfn`, `exp`, `fn`, `cl`, `if`, `match`, `for`, `try`, `map`, `filter`, `each`, `reduce`, `serve` — веб-сервер, а также `cond=`, `cond~`, `cond?` — заготовки условий в стиле morzebot |

## Настройки

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `mzs.path` | `mzs` | путь к исполняемому файлу |
| `mzs.time` | `true` | проверять и запускать с `--time` (иначе `include time`/`include date` — ошибка) |
| `mzs.diagnostics.enable` | `true` | включить проверку |
| `mzs.diagnostics.delay` | `300` | задержка после ввода, мс |
| `mzs.completion.enable` | `true` | включить автодополнение |

`mzs.time` включён, чтобы файл проверялся так, как он будет запущен. Выключите его, чтобы
увидеть файл глазами встраивающего хоста, который эту возможность не даёт. Модулю `http`
флаг не нужен — он стоит всегда.

## Про иконку

Иконка есть в двух видах, и это разные механизмы VS Code.

**1. Иконка языка** (`contributes.languages[].icon`) — работает с вашей текущей темой иконок,
если та поддерживает языковые иконки и сама ничего не знает про `.mzs`. Так ведёт себя тема
по умолчанию (Seti). Если стоит, например, Material Icon Theme, выигрывает она и рисует свою
«безымянную» иконку — это ограничение VS Code, а не расширения.

**2. Тема иконок «mzs (Seti)»** — на случай, когда иконка нужна всегда:

```
Ctrl+Shift+P → Preferences: File Icon Theme → mzs (Seti)
```

Это тема Seti из VS Code целиком (те же иконки для 233 расширений файлов, тот же
`seti.woff`) плюс одна запись: `.mzs` рисуется логотипом, отдельно для тёмной и светлой
темы. У тем иконок в VS Code нет наследования — тема задаёт либо всю таблицу, либо ничего, —
поэтому таблица скопирована, а не унаследована. Копию делает скрипт, а не руки:

```sh
node editors/vscode/icons/theme/build.js
# или, если VS Code лежит нестандартно:
node editors/vscode/icons/theme/build.js /path/to/vscode/resources/app
```

Запускайте его после обновления VS Code, чтобы подхватить новые иконки Seti.
Seti распространяется по MIT (упаковка Microsoft поверх MIT jesseweed/seti-ui);
`icons/theme/ThirdPartyNotices.txt` копируется вместе с ней.

`icons/logo-128.png` — иконка расширения в галерее (там допустим только PNG).

## Откуда берутся подсказки

`data/api.json` **сгенерирован**, а не написан руками: список методов снят с живого реестра
интерпретатора (`mzs.MethodNames`/`BuiltinNames`), описания разобраны из таблиц SPEC.md §12.
Поэтому автодополнение не может предложить метод, которого нет в реализации.

Покрытие описаниями — 290 из 304 записей (95%). Остальные 14 существуют в коде, но не описаны
в таблицах SPEC §12 (`bool.&`, `range.step`, методы значения `time`) — они дополняются, но при
наведении честно сообщают, что описания в спецификации нет.

Пересобрать данные после изменения stdlib: см. `editors/vscode/data/README.md`.

## Ограничения

* Тип получателя выводится только из литерала слева от точки. Для переменной
  (`s.` где `s = "..."`) предлагается объединение методов всех типов — это список длиннее
  нужного, но он никогда не врёт о существовании метода. Исключение — модули: они известны
  точно, потому что их приносит `include` в этом же файле.
* Экспорт соседнего модуля читается регуляркой по его тексту, а не разбором: `export`
  внутри строки или комментария попадёт в список. На диагностику это не влияет — её делает
  сам `mzs --check`.
* Грамматика различает регулярку и деление по тому же правилу, что и лексер (SPEC §3.8), но
  средствами TextMate — в редких выражениях вроде `a /b/ c` подсветка может ошибиться там,
  где сам интерпретатор разбирает верно.
* Нет «перейти к определению» и переименования: для этого нужен language server, а не
  подсветка. Если понадобится — это следующий шаг, интерпретатор уже отдаёт AST через
  `mzs --ast`.
